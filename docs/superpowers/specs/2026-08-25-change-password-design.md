# 登录后修改密码设计

## 目标

为已登录用户提供不依赖邮箱的密码修改能力。用户必须验证当前密码；修改成功后继续保持当前会话有效，同时撤销该账号的其他会话。

## 范围

- 新增受登录态、CSRF 与现有限流机制保护的 `POST /api/auth/change-password`。
- 请求体为 `currentPassword` 与 `newPassword`。
- 新密码沿用现有 10–128 UTF-8 字节密码策略，并使用 Argon2id 保存。
- 当前密码不正确或新密码不符合策略时返回统一、可操作的错误，不泄露密码哈希或账户信息。
- 修改成功时提升用户 `session_version`，撤销其他会话，并旋转当前会话及 CSRF 凭据，使当前浏览器保持登录。
- 在登录后的账户区域新增“修改密码”入口与弹窗，包含当前密码、新密码、确认新密码三个字段。

## 数据流

1. 前端校验新密码与确认密码一致，然后通过现有 `apiFetch` 提交请求。
2. 后端读取当前用户及密码哈希，验证当前密码和新密码策略。
3. 后端在同一事务中更新密码哈希与 `session_version`，撤销该用户全部旧会话。
4. 后端创建新的当前会话、旋转 CSRF，并返回新 CSRF token。
5. 前端更新内存中的 CSRF token、关闭弹窗并显示成功提示。

## 错误与安全

- 未登录返回 401，缺失或无效 CSRF 返回 403。
- 当前密码错误返回 400；响应不包含哈希、令牌或内部错误。
- 新密码不符合策略或两次输入不一致时不修改任何状态。
- 审计日志只记录事件类型和结果，不记录密码。
- 成功修改后，旧会话和旧 CSRF 均不可继续使用。

## 测试

- 后端接口测试覆盖：正确修改、错误当前密码、弱新密码、无登录态、无效 CSRF。
- 会话测试覆盖：当前浏览器获得新会话，其他旧会话失效，旧密码不能登录，新密码可以登录。
- 前端客户端测试覆盖请求字段和新 CSRF token 更新。
- 运行服务器测试、前端测试和生产构建。

## 非目标

- 不新增短信、安全问题或恢复码。
- 不改造现有邮件重置流程。
- 不允许管理员在网页中无验证地替其他用户设置密码。
